## 1. F37 — the gate is `python -m harness.gate`

The three-probe protocol lived in `docs/evidence/step3t/gate.js`, a JS
runner. lex had no lever for it, which is why `/evals` printed a NOT RUN
HERE caveat about its own blind spot. It is now a harness command with the
same shape as every other lever, and lex can pull it.

**The instrument-continuity clause is enforced as bytes, not as intent.**
`tests/test_gate.py` reads the archived `gate.js` and asserts the port
matches it on the preamble, the three probes, each probe's `extra` line, and
the verdict enum. One test reconstructs gate.js's prompt construction and
asserts the port emits the same bytes for all three probes.

**That test caught a real divergence in this build, and it is worth naming
because I introduced it.** My first port appended a "respond in JSON"
instruction into the prompt. gate.js does not: it constrains shape
out-of-band with a `schema` parameter, so its prompt is protocol text only.
The verdicts would very likely still have matched, and the gate would have
been measuring a different prompt under the same name — F26 recurring, with
a version boundary to hide behind. Shape enforcement now lives in a system
message plus `response_format`, and a test asserts no JSON instruction
reaches the measured text.

### Parity: the obvious run proves nothing, so I ran the de-confound

The naive side-by-side varies two things at once. gate.js runs its probes as
Claude subagents; `harness.gate` posts to xAI. Run that way it produced
**0/3 verdict agreement** — which reads on its face as a failed port and is
in fact uninterpretable.

So I held the model fixed and varied only the instrument: `harness.gate`
built its three prompts, and those exact prompts were judged by Claude.

| probe | gate.js / Claude | gate.py / Claude | gate.py / Grok |
|---|---|---|---|
| executor:symbol_table | sufficient_with_gaps | sufficient_with_gaps | sufficient |
| executor:affected_symbols | sufficient_with_gaps | sufficient_with_gaps | sufficient |
| tester:affected_symbols | sufficient_with_gaps | sufficient_with_gaps | sufficient |

- **Port effect, model held fixed: 3/3 agree.** This is the parity F37 asked
  for.
- **Model effect, instrument held fixed: 0/3 agree.** Every difference in
  the naive comparison is the model, not the port.

Evidence, hashes and reproduction: `docs/evidence/gate-port/parity.md`,
`verdicts.json`, `gate_py_grok.json`. The prompt files fed to the Claude arm
are literally `harness.gate.build_prompt(...)` output, so the middle column
is the port's own construction rather than a re-transcription of it.

I record the byte-identity test as the stronger evidence and the verdict
table as the weaker: three probes agreeing once is consistent with
continuity but does not establish it, whereas the test runs every suite
forever.

## 2. F38 — NEW, non-blocking: the model is part of the instrument

Grok returned `sufficient` on all three probes with **zero** missing items.
No verdict in this loop's history has been `sufficient`; the same packets,
through the same prompt, were judged 4–6 misses each by Claude minutes
earlier.

A gate whose probes never report a gap is not measuring packet sufficiency.
The misses are the telemetry, and this arm produced none. So: gate results
are comparable across the **port** boundary and **not** across a model
boundary.

This is filed, not acted on. It bears on standing stop-routing — a gate
result's blocking force currently depends on which model answered — and that
is a ruling, not an implementation detail. **Candidate readings, none
adopted:** (a) the gate is pinned to a model class and dispatches on other
providers still gate on the pinned one; (b) the gate stays authoritative and
provider variance is accepted as recorded noise; (c) the gate becomes
advisory and stop-routing keys off something else. I have no evidence
favouring one, and one three-probe sample on one provider is not enough to
pick.

lex, run on Grok and told the numbers, reached the same conclusion
independently and recommended a ratification prompt rather than adopting a
reading (§4).

## 3. F36 landed — the qualifier retired live, and the fix found a second error

The ratified fix: an inbound handoff must be committed before dispatch. Raw
`--handoff` now raises `DispatchError` naming F36 and pointing at
`--handoff-path`, so the failure cannot recur through the channel that
caused it.

**Citability became a per-packet fact.** The global `F36_OPEN` flag was
marking every replay line NOT CITABLE, including packets that never carried
a handoff at all. `_handoff_replayable(record, packet_path)` now reads the
packet's own `## State — handoff` section: a packet whose handoff section is
empty replays fine whatever the record says. Output now reads
`2 DIVERGED, 2 IDENTICAL` with only **3d-1r and 3d-2** — the two that carry
uncommitted handoffs and can never replay — marked NOT CITABLE.

Worth stating plainly: the blanket flag was suppressing 3b's and 3d-1's true
IDENTICAL verdicts. That is the same class of error F36 is about, pointing
the other way — a citation guard that over-claims uncertainty is still a
guard reporting something other than what it measured. Landed before the
13th as ordered; the qualifier has retired live for everything except the
two packets where it is true.

## 5. Telemetry — lex's first self-reported cost datapoint

```
tokens — grok-4: 5 turns, in 15,112, out 2,163, cache read 52,992
  (counts are normalised across vendors: cache reads are never included in the input column)
  (no price table is asserted here — these are tokens, not dollars)
```

The line prints at session end and is written into the session log, so a
report citing this session's cost cites a recorded figure.

Two decisions inside it:

**The vendors do not agree on what a prompt token is.** Anthropic's
`input_tokens` excludes cache reads; xAI's `prompt_tokens` includes them,
with the cached count broken out underneath. Summing the raw fields would
overcount every cached turn, so `from_openai` subtracts, and a test pins the
subset semantics. Without that, this session would have read as ~68k input
instead of 15k.

**No price table.** Rates change and I would be writing them from memory; an
invented cost is worse than no cost, and it would be cited in a later report
as though measured. Tokens are the datapoint.

A turn whose usage the vendor withholds is counted as `unreported`, not as
zero, and the render says the total is short by that much.
