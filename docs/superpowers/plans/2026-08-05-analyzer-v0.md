# Analyzer v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stdlib-only Python CLI (`analyzer`) that indexes a Python repo at a commit and answers: where is a symbol defined, who references it, and what did a diff affect.

**Architecture:** Pure-`ast` two-pass indexer. Pass 1 walks every `.py` file and builds a symbol table (dotted path, ranges, `sig_hash`, `body_hash`). Pass 2 walks again with a scoping model (imports + local-binding shadowing) to attach `referenced_by` sites and emit unresolved-site records. `affected` builds both commits' indexes in memory from git blobs (no checkouts) and classifies per-symbol by hash comparison. Deterministic JSON serialization throughout.

**Tech Stack:** Python 3.13, stdlib only at runtime (`ast`, `hashlib`, `json`, `argparse`, `subprocess` for git). Tests: pytest.

## Global Constraints

- Runtime dependencies: **stdlib only**. Test dependency: pytest.
- Parser: **`ast` stdlib module** — no tree-sitter (brief Non-goals).
- No dataflow, no type inference, no other languages, no SCIP, no daemon/server/db/cache (brief Non-goals).
- Identity of a symbol is `path` + `sig_hash` + `body_hash`. Line ranges are per-commit derivatives, never identity.
- "When in doubt, flag it" — never substitute a guess for an unresolvable target.
- Indexing the same commit twice → **byte-identical** output file.
- `analyzer index` on a 20k-line repo: **< 10 seconds** (target < 2s).
- Open questions from the brief are left as `TODO` comments at the site, not decided.
- All work on branch `feat/analyzer-v0`; small commits; messages say why.

## Design decisions (locked before task breakdown)

### D1. Module path

`file → module path`: strip `.py`, replace `/` with `.`; `pkg/__init__.py → pkg`; paths are relative to the repo root being indexed. `src/config.py → src.config`.

### D2. Index JSON schema (one file, default `index.json`)

```json
{
  "version": 1,
  "commit": "<full sha>",
  "symbols": [
    {
      "path": "src.config.load_settings",
      "kind": "function",
      "file": "src/config.py",
      "start_line": 40,
      "end_line": 58,
      "signature": "(path: str, strict: bool = False) -> dict[str, str]",
      "sig_hash": "7c2e91a4",
      "body_hash": "91ab3f02",
      "parent": "src.config",
      "confidence": "high",
      "referenced_by": [
        {"file": "src/app.py", "line": 12, "in_symbol": "src.app.boot",
         "kind": "call", "args": ["'./conf.yml'", "True"]}
      ]
    }
  ],
  "unresolved": [
    {"file": "src/router.py", "line": 18, "in_symbol": "src.router.dispatch",
     "reason": "subscript_call", "expression": "HANDLERS[name](payload)"}
  ]
}
```

- `commit` is the resolved full SHA when `--commit` is given, else `null` (working-tree index).
- `kind` ∈ `function | async_function | class`. Methods keep `kind: "function"` with `parent` = class dotted path.
- Reference records: `kind` ∈ `call | name` (`name` = non-call reference: passed as value, decorated target, etc.; no `args` key). Ambiguous references (see D5) additionally carry `"ambiguous": true` and a `"note"` string.
- Ordering (determinism): `symbols` sorted by `(path, start_line)`; each `referenced_by` sorted by `(file, line, in_symbol)`; `unresolved` sorted by `(file, line, reason)`. Serialized with `json.dumps(..., indent=2, sort_keys=True)` + trailing newline.

### D3. Hashes

Both hashes are `sha256(canonical_string.encode()).hexdigest()[:8]`.

- **`sig_hash`** canonical string for functions:
  `name(<params>)-><return>` where each param renders as `<name>:<unparsed annotation or empty>:<'=' if it has a default else empty>`, in order, with positional-only `/`, bare `*`, `*args`, `**kwargs` markers preserved. Default **values** are excluded — only presence (brief: "defaults presence"). Decorators excluded.
  Example: `load_settings(path:str:,strict:bool:=)->dict[str, str]`.
- **`sig_hash`** for classes: `name(<unparsed base list + keywords>)`, e.g. `Loader(Base,metaclass=Meta)`. Changing a base is a signature-level change (callers affected) — the conservative analog of a parameter list.
- **`body_hash`**: `"\n".join(ast.unparse(stmt) for stmt in node.body)`. Unparsing drops comments/blank lines/formatting for free. Docstrings are part of the body and DO affect `body_hash` (they are semantic, not comments). A class's `body_hash` includes its methods' source, so a method edit also reports the class as `body`-changed (owner only) — accepted and documented.
- **`signature` display string** (human-facing, not identity): `ast.unparse` of the arguments plus ` -> <return>`, i.e. `(path: str, strict: bool = False) -> dict[str, str]`. For classes: `(<bases>)` or `""` if no bases.

### D4. Symbol extraction

- Nodes: `FunctionDef`, `AsyncFunctionDef`, `ClassDef`, anywhere in the file.
- `start_line = min(node.lineno, first decorator lineno)`; `end_line = node.end_lineno`.
- Dotted path threads through enclosing classes AND enclosing functions (`src.mod.Outer.inner` / `src.mod.make_handler.handler`). Nested functions get their own entries (TODO comment at site: brief open question — own entries vs fold into parent).
- Module-level constants are NOT indexed (TODO comment at site: brief open question).
- A file that fails to parse produces zero symbols and one `unresolved` record with `reason: "parse_error"` (beyond the brief's minimum reasons — flag, don't guess).

### D5. Reference resolution (the scoping model)

Per file, pre-passes before the reference walk:

1. **Import table**: `import a.b` binds `a` → package `a` (attribute chains resolve through it); `import a.b as m` binds `m` → `a.b`; `from a import f` binds `f` → `a.f`; `from a import f as g` binds `g` → `a.f`; relative imports resolve against the current package. `from a import *` → `star_import` unresolved record, no bindings.
2. **Local-binding sets**: for each function scope, the set of names bound anywhere in it (params, assignments, for/with/except targets, comprehension targets, nested defs, local imports) — matching Python's actual scoping (a name assigned anywhere in a function is local throughout).

Resolution of a loaded `Name` or `Attribute`:

- `Name` bound as a function-local (and not by an import) → **skip** (shadowed; a local named `load_settings` is not the module function).
- Else resolve through: enclosing function scopes → module-level definitions → import table. Hit in symbol table → exact reference.
- `Attribute` chains: resolve the leftmost `Name` to a module path via the import table, append attribute parts, look up in the table (`m.f` with `import src.config as m` → `src.config.f`).
- `self.x` / `cls.x` inside a method → look up `<current class>.x`; on miss, fall through to name-match.
- `Cls().m(...)` — attribute of a call whose func resolves to an indexed class → exact reference to `Cls.m` if it exists.
- **Name-match fallback (over-report, per brief):** an attribute access whose base cannot be resolved (`obj.load()` on an unknown object) is matched against every indexed **method** (symbol whose parent is a class) with the same terminal name. Each match is recorded with `"ambiguous": true, "note": "attribute name match; receiver not statically resolvable"`. No caps; noise is preferred to silence.
- References are collected from every expression context — call sites, decorator expressions, default values, base-class lists, plain loads.
- `in_symbol` = dotted path of the nearest enclosing indexed symbol; module path for module-level sites.
- Call args: `ast.unparse` of each positional arg as written; keywords as `name=value`; `*x` / `**y` as written.

### D6. Unresolved sites

Detected during the same walk (brief's five minimum reasons + `parse_error`):

| reason | trigger |
|---|---|
| `subscript_call` | `Call` whose `func` is a `Subscript` |
| `getattr_call` | any `Call` to builtin `getattr` (not locally rebound), immediately called or not — over-flag |
| `attribute_of_call` | `Call` whose `func` is a `Call` (`factory()(...)`), or whose `func` is an `Attribute` on a `Call` that does **not** resolve to an indexed class |
| `star_import` | `from x import *` anywhere in the file |
| `dynamic_attribute` | any `Call` to builtin `setattr`, or a def of `__getattr__` / `__setattr__` / `__getattribute__` (module- or class-level) |
| `parse_error` | file does not parse |

Any file with ≥ 1 unresolved record → every symbol defined in that file gets `confidence: "low"`, else `"high"`.

### D7. Affected classification

Inputs: old index, new index (both built in memory from git blobs: `git ls-tree -r --name-only <rev>` for the file list, `git cat-file --batch` for contents — no checkouts, no worktrees). Diff: `git diff --no-renames --unified=0 <old> <new>` parsed for changed files and `@@` ranges.

**Documented deviation from the brief's method §4.2:** pure range-intersection cannot satisfy the brief's own `moved` acceptance criterion — an import inserted at the top of a file (outside every symbol's range) intersects nothing, yet every symbol below it must report `moved`. So: ranges identify *changed files*; classification compares the **full symbol sets** of each changed file across the two indexes (cheap — hash comparison per symbol). Rationale recorded here and in `affected.py`.

Per symbol path present in either index for a changed file:

| condition | category | effect column |
|---|---|---|
| in both, `sig_hash` differs | `signature` | `callers affected (N)` — N = old index `referenced_by` count (they were written against the old signature); call sites listed with `--verbose`-free default output naming each site |
| in both, only `body_hash` differs | `body` | `owner only` |
| in both, hashes equal, `start_line`/`end_line` differ | `moved` | `no effect` |
| in both, hashes and lines equal | omitted from report | — |
| old only | `deleted` | error if old `referenced_by` non-empty → nonzero exit, sites listed |
| new only | `added` | `new symbol` |

File rename appears as delete + add of every contained symbol (`--no-renames`; TODO comment at site: brief open question — rename identity).

Output: aligned columns `path  category  effect`, sorted by path. `signature` rows are followed by indented `caller: file:line (in_symbol)` lines so the criterion "names every call site" is met. Exit 1 if any `deleted` symbol had callers, else 0.

### D8. CLI contract

```
analyzer index <repo> [--commit REV] [-o index.json]     # writes index; deterministic bytes
analyzer symbol <path> [--index index.json]              # definition + signature + every caller; exit 1 if unknown
analyzer affected <old-rev> <new-rev> [--repo .]         # table above; exit 1 on deleted-with-callers
analyzer unresolved [--index index.json]                 # all unresolved records
```

- Package runs as `python -m analyzer` (tests use this) and installs a console script `analyzer` via `pyproject.toml`.
- `index` with `--commit` reads blobs from git (only tracked `.py` files at that rev); without it, walks the working tree (skipping dot-dirs, `__pycache__`, `venv`, `.venv`, `node_modules`).
- `affected` needs no saved index; it builds both in memory.

## Post-red-team amendments

A three-critic design review (workflow `wf_2e59c60f`, findings archived in the
session transcript) surfaced 20 defects in D5–D8. All are accepted; where they
change the design, the amendment below supersedes the section above.

**A1 — Scope frames with binding origins (supersedes D5.2 and D5's skip rule).**
Resolution walks a stack of frames (module / class / function / comprehension).
Each binding records its origin: `param`/`assign`-like origins are opaque
(shadowing → skip); `import` origins carry dotted targets; `def`/`class` origins
carry the indexed symbol path (so calls to nested defs resolve instead of being
dropped as shadowed locals). Class frames are invisible to lookups from nested
functions (Python semantics). Comprehensions are their own frame — their targets
do not leak into the function scope. `global`/`nonlocal` declarations remove the
name from the local frame (`global` resolves at module level).

**A2 — Import bindings are multi-target.** A name bound by several imports
(try/except fallback imports) keeps every target; each candidate gets a
reference marked `ambiguous`. Function-local imports bind in their own frame.

**A3 — Re-export chasing and src-layout suffix match (supersedes "hit in
table" rule).** A dotted target that misses the symbol table is chased ≤10 hops
through the target module's own import table (resolves `pkg/__init__.py`
facades). Still missing, its module part is suffix-matched at dot boundaries
against indexed module paths (`mypkg.config` → `src.mypkg.config`), matches
marked `ambiguous`. A from-import whose module part matches indexed modules but
whose target still resolves nowhere → unresolved record, reason
`unresolved_import_target`. Targets matching no indexed module are external —
silent by design (no in-repo edge can hide there).

**A4 — Name-match fallback covers ALL indexed symbols** (not just methods), so
`plugin_module.setup()` reaches module-level `setup` definitions. Zero-match
attribute sites stay silent: every in-repo definition is indexed (or its file is
`parse_error`-flagged), so a terminal name matching nothing indexed cannot hide
an in-repo edge — `parts.strip()` does not flood the report.

**A5 — Attribute-on-call resolution ladder (supersedes the D6
`attribute_of_call` extension).** `Cls().m(...)`: exact when `Cls` is indexed
and defines `m`; miss → name-match fallback (never silently dropped — covers
inherited methods). `super().m(...)`: resolved through the enclosing class's
indexed base chain; miss → name-match. General attribute-on-call
(`open(p).read()`): exact/name-match/silent — NOT flagged unresolved (else
every chained stdlib call marks its file low-confidence and the signal
collapses). Call-of-call `factory()(...)` remains always flagged (brief
minimum shape).

**A6 — Duplicate dotted paths are legal** (property/setter pairs, `@overload`
stacks, platform-conditional defs, `pkg.py` + `pkg/__init__.py`). Nothing keys
on bare path: the internal index maps path → list of records; `referenced_by`
attaches to every record of the path; `analyzer symbol` prints all records.
Sort key extended to `(path, file, start_line, sig_hash, body_hash)` (total
order).

**A7 — Affected classification is per-path over hash multisets (supersedes
D7's table mechanics).** For every path with a record in a changed file (either
side), gather ALL records for that path from BOTH full indexes (not per-file
slices — a module→package refactor is `moved`, not delete+add). Compare:
sig-multiset (of `(kind, sig_hash)`) differs → `signature`; else body-multiset
differs → `body`; else decorator-multiset differs → `decorators` (callers
affected — behavior changes even though the brief's two hashes can't see it);
else position-multiset differs → `moved`; else omitted. Path absent from one
side entirely → `deleted`/`added`.

**A8 — `kind` participates in signature comparison** (`def` → `async def` is
caller-breaking and both brief hashes are blind to it).

**A9 — Records gain `decor_hash`** (sha256[:8] of unparsed decorator list;
not part of the brief's identity triple — used only by A7).

**A10 — Working-tree file listing** uses `git ls-files --cached --others
--exclude-standard -- '*.py'` when the target is a git repo (parity with
`--commit` on tracked dot-dirs), directory walk only for non-repos; both modes
sort the full list before processing.

**A11 — Documented sig_hash deviation.** The canonical signature keeps
positional-only `/`, bare `*`, `*args`/`**kwargs` markers. The brief's coverage
list ("nothing else") excludes them, but `f(a, b)` → `f(a, *, b)` breaks call
sites and must not classify as `moved`. Deviation noted here and at the site.

**A12 — Deviations register.** D7 file-level comparison (plan §D7), A5
selective non-flagging of external chained calls, A7 `decorators` category,
A8 kind-in-signature, A11 marker inclusion — each chosen so that no real
change is reported weaker than it is, and no unknowable-target site with a
possible in-repo edge goes unflagged.

## Post-verification fixes (2026-08-06)

An adversarial verification workflow (`wf_05fa3598`: five hunter lenses, one
independent skeptic per finding) confirmed 7 defects, refuted 1 (default-value-
only change omitted from `affected` — intentional per D7/A7/A12, since the
brief pins sig_hash to defaults *presence*). All 7 fixed, each with tests:

- **V1 (high)** — the outermost comprehension iterable is evaluated in the
  enclosing scope (Python semantics); it was resolved inside the comprehension
  frame, silently dropping references (incl. class-body registry patterns).
- **V2** — a name bound by both an import and a def (try/except
  import-or-define) now keeps BOTH candidates, referenced ambiguously; the
  def no longer wins outright.
- **V3** — `RecursionError` on deep-but-legal trees (generated chained binops)
  degrades to a per-file `parse_error` record instead of killing the run;
  recursion limit raised to 10k.
- **V4** — assignment-form `__getattr__ = fn` (PEP 562) at module/class level
  now flags `dynamic_attribute` like the def form.
- **V5** — corrupt / wrong-shape / unreadable index files and unwritable `-o`
  paths produce one-line `analyzer:` diagnostics, not tracebacks.
- **V6** — a changed file that fails to parse at one rev classifies its
  symbols `unknown` ("assume affected"; error exit if callers recorded) rather
  than a definitive `deleted`/`added`.
- **V7** (dogfooding on 37k lines of pytest internals) —
  `unresolved_import_target` now fires only when the source module has a star
  import (the one case that can hide a def); importing a constant from a
  clean indexed module is provably not a def edge and stays silent. This took
  real-code low-confidence from 91% to 79%, all remaining flags genuine.
