### the P6 leak the red-team demonstrated, and its fix

A prose `types` line has no `(`, so terminal extraction produced `""` and
the word-boundary guard compiled to `\b\b` — which matches any text. Every
node's **tester** packet was receiving foreign type lines. Measured before
the fix: gitio 3, reference_map 3, unresolved_sites 4. A blind tester for
git plumbing was being handed the index's imports contract. Packet assembly
now cuts the terminal the way speccc's anchor check already did; locked by
`test_prose_type_line_does_not_leak_into_other_nodes_packets`.

This is worth naming plainly: the leak was introduced by D1-B's prose line
and would have been doubled by this round's entry. It was invisible to
every gate, because the gate reads packets for sufficiency, not for
containment.

### F28 — bound by target, not by environment (DEVIATION, flagged)

The ruling says env-bound. **Env-binding has no injection point here**:
`dispatch.py` has no spawn step by design, an operator cannot set a
variable for an in-process subagent, and a session-global variable would
misbind whenever two dispatches are live — as two were in the session that
filed F28. So the fence binds from the **target path** first, which
achieves the ruled intent (a subagent is bound to the dispatch it actually
touches) without the misbinding. `LEX_FENCE` remains as an explicit
override. Tell me if you want the env form regardless and I will build it.

**The finding that would have shipped the whole thing inert:** the
PreToolUse matcher was `Write|Edit|NotebookEdit|Bash`. Read/Grep/Glob never
reached the hook, so a tester's hard read fence would have been decorative
and the canary would still have reported the wall live. Matcher extended;
this is why the canary now states what it cannot prove.

### F29 — reads aren't forbidden; invisible reads are

- **tester (hard):** `.harness` only. A **pathless Grep/Glob is refused** —
  searching the tree is the P6 leak itself, and it is the ordinary way an
  agent searches.
- **executor (disclose):** its own write scope and `.harness` are in-packet;
  anything else appends an atomic read event. Bash read shapes
  (`cat|head|tail|sed -n|rg|grep|awk`) are disclosed too — without that,
  3d-1's actual offence reproduces as `sed -n '1,270p' analyzer/refs.py`
  with zero telemetry.
- Events land under a **distinct record key** (`reads_out_of_packet` +
  `self_served_misses`), not `miss_log`, which has counted request_mem gaps
  since 3a. Reusing it would have put a schema change into the ledger's miss
  column and called it behaviour.
- Scoping the executor's in-packet set matters more than it sounds: without
  it, the mandated packet read and the write-scope file it must Read before
  Edit would each count as a self-served miss, reporting ~50 where the true
  count is 1.

## STOP — 3d-1 not resumed; addendum PROPOSED

Report 008 carried six blocking REQUEST_MEM lines. The ruling closes two
(origin semantics, the `module` parameter). These four remain, and the
first is not an omission but a shape problem:

1. **The `kind: module | symbol` enum has no slot for an unresolvable
   import.** `refs.py` emits `star_import` and `unresolved_import_target`;
   such a binding has neither a module nor a symbol kind and no resolved
   terminal, so under the ruled entry there is **no legal entry to emit**.
2. **Key-presence.** Does a file with no imports get an entry? A file that
   fails to parse? It changes byte output, so bullet 1 depends on it.
3. **`import_origins`' return contract.** `list[str]` of what — importing
   files, or origins? Deduplicated? Sorted?
4. **Legacy indexes.** `load_index` validates only `symbols` and
   `unresolved`, so a pre-key index reaches the function and raises.
