## F36 (NEW, blocking for replay) — the handoff channel breaks packet replay

**The cargo found this on its first real run**, which is the best argument for
having built it.

`evals` reports **2 DIVERGED, 2 IDENTICAL**. The two divergent packets are
3d-1r and 3d-2 — the only two dispatches I injected a handoff into. The cause,
confirmed rather than assumed:

```
$ python -m harness.join replay index_assembly --commit f146eb16d654 --shipped docs/evidence/step3d1r/packet.md
DIVERGED  node=index_assembly role=executor commit=f146eb16d654
@@ -615,155 +615,5 @@
  ## State — handoff  [provenance: agent-authored, claim not fact]
 -Carried forward from dispatch 3d-1 ...
```

The divergence is **entirely** the handoff section, empty on rebuild.

**This is mine, introduced in report 010.** Replay's guarantee was that a
packet is reproducible from (spec at commit, join version at commit). A
handoff injected from a scratch file is in neither, so any packet carrying one
is now unreplayable — and F23 was closed on precisely the claim that a
DIVERGED verdict means the packet, not the compiler. That claim is currently
false for two packets on record.

Candidates, none self-ratified:

1. **Commit the handoff before building the packet** (e.g.
   `docs/evidence/stepN/handoff.md`), so it is part of the commit replay reads
   from. Restores the guarantee exactly; costs a commit before each dispatch.
2. **Record the handoff's sha256 in the dispatch record and let replay take
   `--handoff`.** Reproducible given the recorded artifact rather than from
   the commit alone — a weaker guarantee, honestly labelled.
3. **Exclude the handoff section from the comparison.** Cheapest and worst: it
   makes replay silent about the one section a human wrote.

I recommend (1). Note the harvester does not currently copy the handoff at
all, so under any option it should — the input to a dispatch is evidence.
